# 函数·预处理器  
## 特殊函数  
### `@EVENTLOAD`  
数据加载完成后立即调用。  
由于是事件函数，可以定义多个。  
如果没有定义`@EVENTLOAD`，则会转移到`@SHOW_SHOP`（与eramaker相同动作）  

### `@TITLE_LOADGAME`  
在标准标题画面选择加载时被调用。  
通过定义`@TITLE_LOADGAME`，可以在标题画面使用自定义加载画面。  
如果没有定义，将使用标准加载画面。  
如果定义了`@SYSTEM_TITLE`，除非明确使用[`CALL`](../Reference/CALL.md)，否则不会调用`@TITLE_LOADGAME`。  

### `@SYSTEM_AUTOSAVE`  
在自动保存时机被调用。  
可以自定义自动保存的内容。  
如果没有定义，将使用标准保存功能。  

### `@SYSTEM_TITLE`  
在csv加载完成时被调用。  
另外，通过`BEGIN TITLE`也会被调用。  
通过定义`@SYSTEM_TITLE`可以使用自定义标题画面。  
如果没有定义，将使用标准标题画面。  

### `@CALLTRAINEND`  
`CALLTRAIN`自动执行结束后，系统内部自动调用的函数。  
请注意，这不是事件函数，因此不能多重定义。  

## 自定义函数中的参数指定  
<!--※1.54u到1.60版本间规格不同！※  -->  
### 格式  

**函数侧**  

　　　@(函数名),(参数1),{(参数2)....}  
　　　参数为数值时使用ARG(:0,1,2...)，为字符串时使用ARGS(:0,1,2...)  
　　　在函数中使用#DIM、#DIMS定义的私有变量也可以作为参数  

**调用侧**  

　　　CALL (函数名),(参数1),{(参数2)....}  

数值可以使用数值表达式或字符串表达式。  
将字符串字面量（常量）作为参数时，请用`""`括起来。  
将格式化字符串字面量作为参数时，请写成`@"～～"`。  
除了[`CALL`](../Reference/CALL.md)外，[`JUMP`](../Reference/JUMP.md)、CALLFORM、TRYCALL等也可以使用相同格式。  
函数侧可以指定任意多个参数。  
截至ver1.808，函数侧和调用侧类型不同时，无论从数值到字符串还是从字符串到数值，都会出错而不是转换。  
如果想像ver1.807以前一样在字符串型参数中传递数值进行调用，请更改配置设置或使用`TOSTR`函数。  
参数可以省略。省略时，数值型参数为0，字符串型参数为空字符串（未设置初始值的情况下）。  
被调用的函数侧可以通过`ARG`和`ARGS`引用传递的值  
基本上是值传递，因此请注意修改`ARG`内容不会改变传递的原始变量等的值。  
也可以将`ARG`、`ARGS`或函数中使用`#DIM`、`#DIMS`定义的私有变量以外的变量（`A`或`STR`）作为参数，但有几个限制。  
截至ver1.808，使用这些变量时无法设置初始值，也不能省略参数。  

	;定义  
	@FOOBAR, ARG:0, ARGS:0  
		～～  
	@HOGEHOGE, ARG:0, ARG:1, ARG:2  
		～～  
	;调用  
	;用变量指定  
		CALL FOOBAR, X , STR:0  
	;用常量指定  
		CALL FOOBAR, 123 , "あいう"  
	;用格式化字符串指定  
		CALL FOOBAR, 123 , @"[{COUNT}] あいう"  
	;用表达式指定  
		CALL FOOBAR, X + 10, "あいう" * 10  
	;省略参数-全部  
		CALL FOOBAR  
	;省略参数-第1参数  
		CALL FOOBAR, , "あいう"  
	;省略参数-第2参数  
		CALL FOOBAR, 123  

**<会出错的例子>**  

	;错误(参数过多)  
		CALL FOOBAR, X , STR:0, Y  
	;错误(参数类型不同-尝试将字符串赋值给数值型第1参数)  
		CALL FOOBAR, "あいう", "かきく"  
	;错误(参数类型不同-尝试将数值赋值给字符串型第2参数)  
		CALL FOOBAR, 123 , 456  

**<虽然可以运行但不推荐的例子>**  

	;虽然可以不用ARG、ARGS作为赋值目标，但通常建议使用ARG  
	@FOOBAR, X, Y  
	;可以将赋值目标设为可变的，但可读性会降低。  
	@FOOBAR, ARG:X, ARG:Y  
	;可读性会降低。  
	@FOOBAR, ARG:0, ARG:(ARG:0)  

### 参数初始值  
可以为函数参数设置初始值。  
设置初始值时，函数侧如下所示。  

	@(函数名),(参数1 = 初始值1),{(参数2 = 初始值2)....}  
	参数为数值时使用ARG(:0,1,2...)，为字符串时使用ARGS(:0,1,2...)，  
	或函数中使用#DIM、#DIMS定义的私有变量  
	指定其他参数时无法设置初始值。  

可指定的初始值仅限常量和常字符串，不能指定变量。  
另外，字符串初始值请用`""`括起来。  
设置初始值且调用侧省略参数时，会赋值为设置的初始值。  
不省略参数调用函数时，与平常一样，`ARG`和`ARGS`会接收到传递的值。  

	;设置初始值（部分省略也可以）  
	@FUNCTION, ARGS:0 = "かきく", ARG:0 = 111, ARG:1, ARG:2 = 200  
		～～  

	;错误(初始值仅限常量和常字符串)  
	@FOOBAR, ARG:0 = MASTER, ARG:1 = TARGET  
	;对ARG、ARGS、函数中使用#DIM、#DIMS定义的私有变量以外的参数设置初始值会被忽略。  
	;因此无法按预期运行。  
	@FOOBAR, X = 5, Y = 4  

### 参数引用传递  
从ver1.810开始，通过在形参中使用引用型变量可以实现参数的引用传递。  
引用型变量的定义方法请参考[引用型变量](user_defined_variables.md#_6)章节。  

**<xxx.ERB>**  

	@SYSTEM_TITLE  
	A = 0  
	CALL TEST(A)  
	B = 1  
	CALL TEST(B)  
	PRINTFORML A == {A}  
	PRINTFORML B == {B}  
	WAIT  

	@TEST(HOGE)  
	#DIM REF HOGE  
	HOGE = 100  
	RETURN  

**<执行结果>**  

	A == 100  
	B == 100  

在上面的例子中，函数`@TEST`的形参使用了引用型变量。  
第一次调用`@TEST`时，`HOGE`会引用实参`A`。  
在函数`@TEST`中执行`HOGE = 100`时，引用的目标变量`A`被赋值为`100`，所以第一次`PRINTFORML`的结果是`100`。  
同样，第二次调用`@TEST`时，变量`B`被赋值为`100`，第二次`PRINTFORML`的结果也是`100`。  

## 属性  
决定函数规格和动作的预处理器。  
在函数中记录以#开头的预处理器时，必须紧接在函数下方。  

### `#ONLY`  
事件函数专用属性。  
如果指定了`#ONLY`的事件函数存在，只执行这一个，不会执行其他同名事件函数。  
另外，如果有多个指定了`#ONLY`的同名事件函数，也只执行"最初的那一个"。  

### `#FUNCTION`  
表达式函数的属性。  
表达式函数不能用普通的RETURN结束，需要用`RETURNF <数值表达式>`结束。  
详情请参考[用户定义的表达式函数](user_defined_in_expression_function.md)。  

### `#FUNCTIONS`  
表达式函数的属性。  
表达式函数不能用普通的`RETURN`结束，需要用RETURNF <字符串表达式>结束。  
详情请参考[用户定义的表达式函数](user_defined_in_expression_function.md)。  

## 定义  
定义变量名称及其规格的预处理器。  
在函数中记录以`#`开头的预处理器时，必须紧接在函数下方。  

### `#LOCALSIZE <常量表达式>`,`#LOCALSSIZE <常量表达式>`  
为每个函数单独指定`LOCAL`和`LOCALS`元素数量的预处理器。  
常量表达式的结果必须是大于0的整数，其他情况或包含变量的表达式或无法解释的字符串会被忽略。  
被忽略或未使用此预处理器时，按常规使用`VariableSize.csv`的设置值。  
在事件函数中使用此预处理器时，使用最先执行的设置（截至ver1800）。  

### `#DIM`  
用户定义变量声明。在ERB中的特定函数内使用，可以定义仅在该函数内使用的数值型变量。  
详情请参考用户定义的变量。  
另外，在ERH中使用时，可以定义所有函数间共享值的数值型变量。  
详情请参考[头文件（ERH）](ERH.md)。  

### `#DIMS`  
用户定义变量声明。在ERB中的特定函数内使用，可以定义仅在该函数内使用的字符串型变量。  
详情请参考用户定义的变量。 另外，在ERH中使用时，可以定义所有函数间共享值的字符串型变量。  
详情请参考[头文件（ERH）](ERH.md)。  

### `#DEFINE`  
DEFINE宏声明。在ERH中使用时，可以将全ERB代码中的字符串替换为预先定义的另一字符串。  
详情请参考头文件（ERH）。  

## 表示特殊块的行  
这些都是预处理器行。  
在记录这些的同行，不能在紧接其后继续记录指令、函数或注释等。  
这些在eramaker中无法解释，因此在编码时有时需要使用`;!;`。  

### `[SKIPSTART]`～`[SKIPEND]`  
从`[SKIPSTART]`到`[SKIPEND]`之间写的行在Emuera中不会被读取和执行。  
这是有意改变Emuera和eramaker行为时使用的。  
请在不想在Emuera中执行的语句中使用。  
另外，与`;!;`一起使用时，可以在Emuera以外不执行不想执行的语句。  
详情请参考[Emuera中新增的语法](expression.md)章节。  

### `[IF XXX]`～`[ELSEIF XXX]`～`[ELSE]`～`[ENDIF]`  
可以根据名称`XXX`的宏是否定义来决定执行多行或分支。  
详情请参考[头文件（ERH）](ERH.md)。  

### `[IF_DEBUG]`～`[ENDIF]`  
从`[IF_DEBUG]`到`[ENDIF]`之间写的行只在调试模式时执行。  
非调试模式时被视为注释行不执行。  
不过，`DEBUG`系列指令原本在非调试模式时就被忽略，因此不需要在行首添加`;#;`。  
同样，调试变量在非调试模式时也是空字符串或0，不用担心出错。  
关于调试模式请参考[这里](debug.md)。  

### `[IF_NDEBUG]`～`[ENDIF]`  
从`[IF_NDEBUG]`到`[ENDIF]`之间写的行只在非调试模式时执行。  
调试模式时被视为注释行不执行。  
与`[IF_DEBUG]`的判断正好相反。  
关于调试模式请参考[这里](debug.md)。
