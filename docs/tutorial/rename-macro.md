# Renameマクロ：`[[名前]]` コンパイル時置換

!!! tip "この章のポイント"

    - `[[名前]]` は `CSV/_Rename.csv` に基づく**読み込み時の行全体テキスト置換**。表側（左列）＝置換後の値（通常は番号）、裏側（右列）＝ERB で書く表記
    - 置換は字句解析やコメント削除より**前**に行われる。未登録の `[[…]]` は**コンパイルエラー**になる — タイプミスが実行時まで黙って残らない（fail-fast）
    - CSV／ERD／ALS の識別子辞書（名前→添字）とは**別の仕組み**。置換結果は式の任意の位置に埋め込める定数テキスト

---

## Rename とは

Rename は EraMakerEx 由来の簡易マクロ機能で、ERB 中の `[[名前]]` という表記を `CSV/_Rename.csv` に登録された値に置き換えます。元々は「スクリプト内の番号を名前で書けるようにする」ための機能です。

有効化はコンフィグの「`_Rename.csv`を利用する」オプションで行います（**既定は NO**）。このオプションが無効のまま `[[名前]]` を含む ERB を読み込むと、すべての `[[…]]` がコンパイルエラーになります。詳細は[コンフィグの項目](../Emuera/config.md)を参照してください。

## `_Rename.csv` の書式

`CSV` フォルダ直下に `_Rename.csv` を置きます。1 行は `値, 名前` の順です：

```csv
; 左列 = 置換後の値（通常は番号）、右列 = ERB で書く [[表記]]
8,千百合
44,爱莲
44,マイ      ; 複数の名前が同じ値を指すのは OK
```

規則：

| 規則 | 内容 |
|------|------|
| コメント行 | `;` で始まる行は読み飛ばされる（登録を無効化するのに使える） |
| 同名複数行 | 同じ右列が複数ある場合、**後から読んだ行が勝つ**（辞書は 1 つだけ） |
| 一つの名前空間 | ファイル全体が一枚のフラットな辞書。別カテゴリで同名（例：料理とアイテムの両方に「冰淇淋」）だと衝突する — 区別したい側に接頭辞（`ITEM_` など）を付けて回避する |
| エンコーディング | 文字コードは自動判別される |

## 処理の流れ

1. **起動時**：コンフィグが有効なら `_Rename.csv` を読み込み、`[[右列]]` → 左列 の辞書を構築する
2. **読み込み時**：ERB の各行を `\[\[.*?\]\]` の正規表現で走査し、辞書にあれば該当部分を値のテキストで置き換える。この置換は**コメント削除より前**に行われるため、コメント内の `[[名前]]` も置換される
3. **字句解析時**：それでも残った `[[…]]` は**コンパイルエラー**になる

置換は純粋なテキスト置換であり、置換結果（`8` などの番号テキスト）はそのまま式に埋め込まれます。したがって置換後の値は[定数畳み込み](constant-folding.md)や `SELECTCASE` のジャンプテーブル最適化に参加できます。

## 名前→値の仕組みの比較

ERABASIC には「名前で番号を扱う」仕組みが複数あります。役割が異なるので混同しないこと：

| 仕組み | 定義ファイル | 記法 | 未登録時 | 備考 |
|--------|------------|------|---------|------|
| CSV 識別子ファイル | `CSV/変数名.csv` | `ITEM:名前`、`GETNUM` | 実行時に解決されない（`GETNUM` は -1） | エンジン内蔵変数の名前定義 |
| ERD | `ERB/変数名.erd` | 同上 | 同上 | `#DIM` 広域変数の名前定義 |
| ALS（別名） | `.erd`/`.csv` と同名の `.als` | 同上（別名も可） | 同上 | 同じ添字に別名を追加 |
| **Rename（本ページ）** | `CSV/_Rename.csv` | `[[名前]]` | **コンパイルエラー** | 値テキストを式の任意の位置に埋め込む |
| `#DIM CONST` / `#DEFINE` | ERH 内 | 裸識別子 | コンパイルエラー | コード側で定義する定数 |

識別子辞書系（CSV/ERD/ALS）は「**変数の名前添字**」専用で、`変数:名前` や `GETNUM` が消費します。一方 Rename は特定の変数に紐づかず、`CASE` の値、算術式、配列添字など**式の任意の位置**に値を埋め込めます。詳しくは[変数識別子：CSV／ALS／ERD](variable-declaration.md#identifiers)を参照してください。

## 使い方の例

```erb
; CASE の値を名前で書く（[[おにぎり]] → 101 に置換される）
SELECTCASE FLAG:料理
    CASE [[おにぎり]]
        PRINTL おにぎりだ

; 算術式の中で（オフセット + キャラ番号）
CASE DISH_CHARA_OFFSET + [[千百合]]    ; → DISH_CHARA_OFFSET + 8

; 単純な値の確認
PRINTV [[千百合]]    ; → 8
```

整数を比較する文脈では、`"名前"` という文字列リテラルと `[[名前]]` の混在に注意してください：

```erb
; ❌ "みかん" は文字列リテラル — ARG が整数なら決して一致しない
SIF GROUPMATCH(ARG, [[りんご]], "みかん")

; ✅ すべて [[名前]] に統一する
SIF GROUPMATCH(ARG, [[りんご]], [[みかん]])
```

## よくある落とし穴

| 落とし穴 | 現象 | 対処 |
|---------|------|------|
| `"名前"`（文字列）と `[[名前]]`（値）の混用 | 整数比較文脈で文字列リテラルが決して一致しない | 比較対象はすべて `[[名前]]` に統一 |
| 未登録の名前 | コンパイルエラー（fail-fast） | `_Rename.csv` に `値,名前` 行を追加する |
| 別カテゴリ同名の衝突 | 後から読んだ行が勝ち、意図しない番号に解決される | 接頭辞（`ITEM_` など）で名前空間を分ける |
| コメント内の `[[名前]]` | コメント削除前に置換されるため、コメントも対象になる | 注釈として名前を書く場合は留意 |
| コンフィグ無効 | すべての `[[…]]` がコンパイルエラー | 「`_Rename.csv`を利用する」を有効化 |
