# 値・型・変数

---

## 3つの型体系

ERABASIC には3つの基本データ型があり、それぞれ独立した宣言キーワード、引数変数、デフォルト値を持ちます：

| 型 | 宣言キーワード | 引数変数 | リテラル例 | デフォルト値 |
|------|-----------|---------|------------|--------|
| 整数 (Integer) | `#DIM` | `ARG` | `42`, `0x2A`, `1p5` | `0` |
| 文字列 (String) | `#DIMS` | `ARGS` | `"hello"`, `@"form"` | `""` |
| 浮動小数点 (Float) | `#DIMF` | `ARGF` | `3.14`, `-1.5e2` | `0.0` |

!!! tip "Float は Skia 変体で追加された型"

    浮動小数点型（`#DIMF` / `ARGF` / `RESULTF`）は Skia 変体で追加された型拡張であり、オリジナルの Emuera ではサポートされていません。
    本チュートリアルは Emuera をベースラインとし、Float 関連の内容は特に注記します。

3つの型の間では**（Int→Float の安全な昇格を除き）自動変換は行われません**。つまり、文字列を整数変数に代入したり、整数を文字列変数に代入したりすることはできません——明示的な変換関数を使わなければなりません。

---

## 整数型

整数は ERABASIC のデフォルトの型です。エンジン内部では 64 ビット符号付き整数（`Int64`/`long`）を使用し、値の範囲は `-9223372036854775808` ～ `9223372036854775807` です。

### 整数リテラル

ERABASIC は複数の整数リテラル表記をサポートします：

| 表記 | 形式 | 例 | 値 |
|--------|------|------|----|
| 10進数 | 数字列 | `42` | 42 |
| 16進数 | `0x` プレフィックス | `0x2A` | 42 |
| 2進数 | `0b` プレフィックス | `0b101010` | 42 |
| 2のべき乗 | `p` サフィックス | `1p5` | 32（1×2⁵） |
| 10のべき乗 | `e` サフィックス | `13e3` | 13000（13×10³） |

```erb
#DIM L_VAL
L_VAL = 42            ; 10進数
L_VAL = 0x2A          ; 16進数
L_VAL = 0b101010      ; 2進数
L_VAL = 1p5           ; 1 × 2⁵ = 32
L_VAL = 13e3          ; 13 × 10³ = 13000
L_VAL = -0xFF         ; -255
L_VAL = 2p10          ; 2 × 2¹⁰ = 2048
```

!!! warning "`e` と `p` は整数リテラルの一部であり、浮動小数点ではない"

    `13e3` は整数 13000 であり、浮動小数点 13000.0 ではありません。`p` は 2 のべき乗、`e` は 10 のべき乗を表します。
    これらのサフィックスは整数リテラルの中でのみ使え、変数名の中では使えません。

    ソース参考：`LexicalAnalyzer.ReadInt64()` は `p`/`P` を2進指数、`e`/`E` を10進指数として解析し、結果は依然として `long` です。

### 整数演算

整数演算は標準の優先順位に従います。除算は**整数除算**（小数切り捨て）です：

```erb
#DIM L_RESULT
L_RESULT = 10 / 3        ; → 3（切り捨て、3.333... ではない）
L_RESULT = -7 / 2        ; → -3（ゼロ向き切り捨て）
L_RESULT = 10 % 3        ; → 1（剰余）
L_RESULT = 7 & 3         ; → 3（ビット論理積）
L_RESULT = 7 | 8         ; → 15（ビット論理和）
L_RESULT = 7 ^ 8         ; → 15（ビット排他論理和）
L_RESULT = 1 << 4        ; → 16（左シフト）
L_RESULT = 256 >> 4      ; → 16（右シフト）
```

!!! skia "Skia 版のオーバーフロー保護（SafeArithmetic）"

    Skia 版では、算術演算子（`+`、`-`、`*`、単項 `-`）にオーバーフロー保護が有効です。演算結果が `long` の範囲を超えた場合、警告を出力し、結果を `Long.MaxValue` または `Long.MinValue` にクランプします（サイレントに回り込むのではなく）。

    回り込みオーバーフロー動作（ハッシュ計算など）が必要な場合は、[UNCHECKED シリーズ関数](../Reference/UNCHECKED.md) を使用してください：

    ```erb
    ; 通常の加算：オーバーフロー時にクランプ + 警告
    ; 9223372036854775807 + 1 → Long.MaxValue

    ; 回り込み加算：オーバーフロー時に折り返し、警告なし
    ; UNCHECKED_ADD(9223372036854775807, 1) → -9223372036854775808
    ```

## 文字列型

文字列型はテキストデータを格納します。文字列リテラルは `""` で囲みます。

### 文字列リテラル

```erb
#DIMS L_NAME
L_NAME '= "艾莉娜"          ; 文字列リテラルは "" で囲む必要がある
L_NAME '= "Hello World"     ; "" がないと変数名として扱われる！
L_NAME '= ""                ; 空文字列
```

!!! danger "文字列リテラルは二重引用符で囲まなければならない"

    ```erb
    ; ❌ エラー：引用符がないと変数名として扱われる
    L_NAME '= hello

    ; ✅ 正しい：引用符を付けると文字列リテラル
    L_NAME '= "hello"
    ```

### 文字列代入の2つの方法

文字列変数には2つの代入構文があり、動作は全く異なります：

```erb
#DIMS L_STR

; = は FORM 構文を通る（変数補間をサポート）
L_STR = 你好，%NAME:TARGET%！    ; %NAME:TARGET% はキャラ名に置換される
L_STR = 金钱：{MONEY}元           ; {MONEY} は金額値に置換される

; '= は式構文を通る（補間なし、連結をサポート）
L_STR '= "你好"                   ; リテラル代入
L_STR '= NAME:TARGET + "的冒险"   ; 文字列連結
L_STR '= "Hello %NAME%"           ; パーセント記号は字面テキスト、補間されない！
```

| | `=` (FORM 構文) | `'= ` (式) |
|------|:---:|:---:|
| `{変数}` 補間 | ✅ | ❌ |
| `%変数%` 置換 | ✅ | ❌ |
| 文字列連結 `+` | ❌ | ✅ |
| 文字列リテラル `""` | 不要 | **必須** |

> 詳細は [代入文](assignment.md) と [FORM 構文](form-syntax.md) を参照。

### 文字列演算

文字列は比較と連結をサポートします：

```erb
; 連結（'=' 代入が必要）
L_STR '= "你好" + "世界"        ; → "你好世界"
L_STR '= L_STR + "！"           ; → "你好世界！"

; 繰り返し
L_STR '= "啊" * 3               ; → "啊啊啊"

; 比較
IF L_STR == "你好"
    PRINTL 匹配
ENDIF
IF L_STR != ""
    PRINTL 非空
ENDIF
```

## 浮動小数点型（Skia 変体で追加）

浮動小数点は独立した `EraType` 列挙値であり、`#DIMF` で宣言する必要があります。エンジン内部では `double`（64 ビット倍精度浮動小数点）を使用します。

### 浮動小数点リテラル

```erb
#DIMF L_FLOAT
L_FLOAT = 3.14              ; 小数点リテラル
L_FLOAT = -1.5e2            ; 科学記法 → -150.0
L_FLOAT = 0.001             ; 小数
L_FLOAT = 10 / 3.0          ; 浮動小数点除算 → 3.333...
```

!!! warning "整数除算 vs 浮動小数点除算"

    ```erb
    #DIMF L_F
    L_F = 10 / 3         ; → 3.0（整数除算後に浮動小数点へ昇格）
    L_F = 10 / 3.0       ; → 3.333...（浮動小数点除算）
    L_F = 10.0 / 3       ; → 3.333...（浮動小数点除算）
    ```

    代入先変数の型は右辺式の計算方法に影響しません。`10 / 3` は常に整数除算で、結果は `3` です；
    オペランドのいずれかに浮動小数点値が含まれる場合にのみ、浮動小数点除算が発動します。

### 浮動小数点演算

```erb
#DIMF L_PI = 3.14159265
#DIMF L_R = 5.0
#DIMF L_AREA

L_AREA = L_PI * L_R * L_R       ; 円の面積
L_AREA = L_R * L_R * L_PI       ; 等価な書き方
```

## 配列の本質：スカラーは存在せず、すべてが配列

ERABASIC に真のスカラー変数は存在しません——**すべての変数は配列です**。これは ERABASIC の変数システムを理解する上での鍵です。

### すべては配列

| 表記 | 本質 | 説明 |
|------|------|------|
| `#DIM L_VAR` | `#DIM L_VAR, 1` | 長さ 1 の一次元配列を宣言 |
| `L_VAR = 10` | `L_VAR:0 = 10` | `L_VAR` は `L_VAR:0` の省略記法 |
| `ARG` | `ARG:0` | 組み込み整数引数配列の最初の要素 |
| `ARGS` | `ARGS:0` | 組み込み文字列引数配列の最初の要素 |
| `LOCAL` | `LOCAL:0` | 組み込みローカル整数配列の最初の要素 |
| `RESULT` | `RESULT:0` | 組み込み戻り値整数配列の最初の要素 |

```erb
#DIM L_VAR              ; 実質 #DIM L_VAR, 1 — 長さ 1 の一次元配列
L_VAR = 42              ; 実質 L_VAR:0 = 42
PRINTV L_VAR            ; 42 を出力
PRINTV L_VAR:0          ; 同じく 42 を出力
```

**`:` は配列要素アクセス識別子**です。`変数名:インデックス` でその変数の N 番目の要素にアクセスします。

### 省略記法がもたらす混乱

`L_VAR` が `:0` を省略できることと、`:` が同時に配列アクセスの区切り文字であることから、変数アクセスがネストした際に解釈の曖昧さが生じます。

#### アンチパターン 1：一次元配列 + 変数添字

```erb
#DIM L_IDX = 5
; ❌ エラー：FLAG は一次元配列なので第二次元を持たない
FLAG:L_IDX:2

; ✅ 正しい：括弧で添字式を囲む
FLAG:(L_IDX:2)
```

`FLAG:L_IDX:2` の誤りは：`FLAG` は一次元配列（`FLAG:0`, `FLAG:1`, ...）ですが、`:L_IDX:2` が第二次元へのアクセスとして解釈される点にあります。正しくは括弧 `(L_IDX:2)` で添字式全体を囲みます。

#### アンチパターン 2：キャラ配列のデフォルト省略トラップ

キャラ配列（`CFLAG`、`TALENT`、`EXP` など）の第一次元はデフォルトで `TARGET` が補完されるため、省略可能です。これにより以下のような紛らわしいケースが発生します：

```erb
#DIM L_VAR = 5
; ❌ 意味エラー：意図は CFLAG:TARGET:L_VAR:0
CFLAG:L_VAR:2

; 実際の解釈過程：
; 1. CFLAG はキャラ配列、第一次元省略 → デフォルト TARGET
; 2. L_VAR:2 が第二次元のインデックスとして解釈 → CFLAG:TARGET:L_VAR:2 へのアクセス
; 3. しかし L_VAR は配列であり、L_VAR は L_VAR:0 に展開される
; 4. 最終結果：CFLAG:TARGET:(L_VAR:0):2 → 誤った次元構造

; ✅ 正しい：キャラ番号を明示する
CFLAG:TARGET:L_VAR
```

`CFLAG:L_VAR:2` は文法チェックを通過しますが、その解釈経路は開発者の意図とは全く異なります。キャラ配列の第一次元は常に明示的に記述することで、この種のトラップを回避できます。

#### アンチパターン 3：変数名が配列インデックスとして誤解釈される

```erb
; ❌ 意味エラー：TALNET は二次元配列、TALENT は変数名
TALNET:TALENT:5

; 実際の解釈：
; 1. TALNET は二次元配列 → 2 つのインデックスが必要
; 2. TALENT が変数名として扱われる → TALENT は TALENT:0 に展開（TALENT もキャラ配列で第一次元は TARGET）
; 3. 全体の式：TALNET:(TALENT:TARGET:0):5 として解釈
; 4. 文法的には正しいが、意味的には開発者の意図と全く異なる
```

`TALNET:TALENT:5` は**文法的に有効だが意味的に誤っている**典型例です。エンジンはエラーを出しませんが、実際には `TALNET:(TALENT:TARGET:0):5` にアクセスしています——`TALENT` 変数の値そのものを TALNET の第一次元インデックスとして使用していることになります。

### ルールまとめ

| ルール | 説明 |
|--------|------|
| **複合添字は常に括弧で囲む** | `FLAG:(L_IDX)` であって `FLAG:L_IDX` ではない |
| **キャラ配列は第一次元を明示** | `CFLAG:TARGET:L_VAR` であって `CFLAG:L_VAR` ではない |
| **変数名が配列インデックスとして解釈され得ることに注意** | `TALNET:TALENT:5` は文法上正しいが意味的に誤ったコード |
| **変数名そのものが `:0` の省略** | `L_VAR` = `L_VAR:0` の理解がすべての混乱の根源 |

> これらのアンチパターンは経験豊富な開発者でも陥りやすい落とし穴です。ERB コードを書く際は、**`:` で区切られた複数の識別子を見たら、必ず解釈経路を確認し、意図と一致しているかどうかを確かめてください**。

## 組み込み変数

ERABASIC には多数の組み込み変数が用意されており、宣言なしに使用できます。以下によく使われる組み込み変数を示します：

| 変数 | 型 | 用途 |
|------|------|------|
| `RESULT` | Int 一次元配列 | 関数の戻り値（`RETURN` で書き込む） |
| `RESULTS` | Str 一次元配列 | 関数の文字列戻り値 |
| `RESULTF` | Float 一次元配列 | 関数の浮動小数点数戻り値（Skia追加） |
| `ARG` | Int 一次元配列 | 関数の整数引数 |
| `ARGS` | Str 一次元配列 | 関数の文字列引数 |
| `ARGF` | Float 一次元配列 | 関数の浮動小数点数引数（Skia追加） |
| `COUNT` | Int | ループカウンタ（`REPEAT` で使用） |
| `TARGET` | Int | 現在の対象キャラクター番号 |
| `MASTER` | Int | 主人公番号（通常は 0） |
| `ASSI` | Int | アシスタントキャラクター番号 |
| `MONEY` | Int | 所持金 |
| `DAY` | Int | 経過日数 |
| `TIME` | Int | 時刻 |
| `LOCAL` | Int 一次元配列 | 関数ローカル整数変数（⚠時代遅れ、新規ゲームでは `#DIM` を推奨、VariableSize.csv に -1 を設定して無効化可能） |
| `LOCALS` | Str 一次元配列 | 関数ローカル文字列変数（⚠時代遅れ、新規ゲームでは `#DIMS` を推奨、VariableSize.csv に -1 を設定して無効化可能） |
| `LOCALF` | Float 一次元配列 | 関数ローカル浮動小数点数変数（⚠時代遅れ、新規ゲームでは `#DIMF` を推奨、VariableSize.csv に -1 を設定して無効化可能） |

> 組み込み変数の完全なリストは [変数仕様](../Emuera/variables.md) を参照してください。

### A～Z 予約変数

**A～Z の 26 文字の単一文字変数はエンジン組み込みの汎用整数配列であり、`#DIM` で宣言してはいけません！**

```erb
; ❌ エラー：A～Z はエンジン組み込み変数
#DIM A
#DIM X

; ✅ 正しい：L_ プレフィックスを使用して衝突を回避
```

これらの変数は `VariableCode` で `__INTEGER__ | __ARRAY_1D__` 型として定義されており、エンジンに予約された汎用ストレージ領域です。コード中で直接 `A:0`、`B:5` のように使用できますが、`#DIM` で再宣言することはできません。

### プライベート変数宣言

関数内で `#DIM`/`#DIMS`/`#DIMF` を使用してプライベート変数を宣言します：

```erb
@MY_FUNC(ARG:0)
#DIM L_COUNT, 10          ; プライベート整数配列、10要素
#DIMS L_NAME              ; プライベート文字列変数（単一要素配列）
#DIMF L_SCORE             ; プライベート浮動小数点変数（単一要素配列、Skia追加）
    L_COUNT:0 = ARG:0
    L_NAME '= "テスト"
    L_SCORE = 0.0
RETURN
```

!!! warning "#DIM は @ ラベル行の後、実行ステートメントの前に必須"

    ```erb
    ; ❌ エラー：#DIM が関数本体の途中に出現
    @MY_FUNC
        PRINTL 開始
        #DIM X, 10        ; → 警告

    ; ✅ 正しい：#DIM は @ 行の後
    @MY_FUNC
    #DIM X, 10
        PRINTL 開始
    ```

> 詳細は [行タイプと構造](line-types.md) および [ERBファイルフォーマット拡張](erb-format-extension.md) を参照してください。

### 配列アクセス

変数名の後に `:` とインデックスを使用して配列要素にアクセスします：

```erb
; 一次元配列
A:0 = 100
A:5 = 200
L_COUNT:3 = 42

; 二次元配列
DA:0:0 = 1
DA:0:1 = 2

; 変数をインデックスとして使用
#DIM L_IDX = 5
PRINTVL A:L_IDX           ; A:5 の値を出力

; 文字列インデックス（CSV で名前マッピングが定義されている場合）
ABL:0 += 1                ; 数値インデックス
ABL:"技巧" += 1           ; 文字列インデックス（abl.csv に定義がある場合）
```

## 型変換

3つの型間で自動変換は行われません（Int→Float の安全な昇格を除く）。異なる型同士の操作には明示的な変換関数を使用する必要があります。

### 暗黙的変換

唯一の暗黙的変換は**実引数→仮引数のバインド**時に発生します：

| 実引数の型 | 仮引数の型 | 動作 |
|-----------|-----------|------|
| Integer | Float | ✅ 安全な昇格 |
| その他の組み合わせ | — | ❌ ブロック |

```erb
@FLOAT_FUNC(ARGF:0)
#FUNCTIONF
    RETURNF ARGF:0 * 2.0

; ✅ 整数 5 が自動的に浮動小数点数 5.0 に昇格
RESULTF = FLOAT_FUNC(5)
```

### 明示的変換関数（TO シリーズ） { #型変換関数 }

| 関数 | 機能 | 例 | 結果 |
|------|------|------|------|
| `TOSTR(int)` | 整数→文字列 | `TOSTR(42)` | `"42"` |
| `TOSTR(int, fmt)` | 整数→文字列（フォーマット） | `TOSTR(42, "D4")` | `"0042"` |
| `TOSTR(int, "X")` | 整数→十六進文字列 | `TOSTR(255, "X")` | `"FF"` |
| `TOSTRF(float)` | 浮動小数点数→文字列（Skia追加） | `TOSTRF(3.14)` | `"3.14"` |
| `TOSTRF(float, fmt)` | 浮動小数点数→文字列（フォーマット） | `TOSTRF(3.14, "F2")` | `"3.14"` |
| `TOINT(str)` | 文字列→整数 | `TOINT("42")` | `42` |
| `TOINT(float)` | 浮動小数点数→整数（Skia拡張） | `TOINT(3.7)` | `3`（切り捨て） |
| `TOFLOAT(str)` | 文字列→浮動小数点数（Skia追加） | `TOFLOAT("3.14")` | `3.14` |

### 型変換完全対照表

| ソース → ターゲット | 暗黙的 | 明示的関数 | 備考 |
|---------------------|--------|-----------|------|
| Int → Str | ❌ | `TOSTR(i)` | オリジナル版 |
| Int → Float | ✅ | — | 安全な昇格 |
| Str → Int | ❌ | `TOINT(s)` | 解析失敗→0 |
| Str → Float | ❌ | `TOFLOAT(s)` | Skia追加；解析失敗→0.0 |
| Float → Str | ❌ | `TOSTRF(f)` | Skia追加 |
| Float → Int | ❌ | `TOINT(f)` | Skia拡張；直接切り捨て |

### 変換例

```erb
; 整数 → 文字列
#DIMS L_STR
L_STR '= TOSTR(42)             ; → "42"
L_STR '= TOSTR(42, "D4")       ; → "0042"（4桁ゼロ埋め）
L_STR '= TOSTR(255, "X")       ; → "FF"（十六進）

; 文字列 → 整数
#DIM L_INT
L_INT = TOINT("42")            ; → 42
L_INT = TOINT("abc")           ; → 0（解析失敗）
L_INT = TOINT("")              ; → 0（空文字列）

; 浮動小数点数 → 文字列（Skia追加）
#DIMF L_PI = 3.14159265
L_STR '= TOSTRF(L_PI)          ; → "3.14159265"
L_STR '= TOSTRF(L_PI, "F2")    ; → "3.14"
L_STR '= TOSTRF(L_PI, "E")     ; → "3.141593E+000"

; 文字列 → 浮動小数点数（Skia追加）
#DIMF L_F
L_F = TOFLOAT("3.14")          ; → 3.14
L_F = TOFLOAT("-1.5e2")        ; → -150.0
L_F = TOFLOAT("abc")           ; → 0.0（解析失敗）

; 浮動小数点数 → 整数（Skia拡張）
L_INT = TOINT(3.7)             ; → 3（切り捨て、四捨五入ではない）
L_INT = TOINT(-2.9)            ; → -2（ゼロ方向への切り捨て）
```

!!! warning "TOINT は浮動小数点数を切り捨てるのであり、四捨五入ではない"

    `TOINT(3.7)` は `3` を返し、`4` ではありません。ソースコードの実装は `(long)GetFloatValue()` であり、C# の直接キャストでゼロ方向へ切り捨てます。

### FORM 構文での変換の使用

フォーマット文字列に非整数型の値を挿入する必要がある場合、変換関数は特に便利です：

```erb
; PRINTFORM で浮動小数点数値を挿入（Skiaバリアント）
#DIMF L_PI = 3.14159265
PRINTFORML 円周率：%TOSTRF(L_PI, "F2")%    ; → "円周率：3.14"（TOSTRFは文字列を返すため、{}ではなく%...%を使用）

; 文字列代入で連結
#DIMS L_MSG
L_MSG = 円周率は%TOSTRF(L_PI, "F4")%       ; FORM構文、%...% 文字列置換
L_MSG '= "円周率は" + TOSTRF(L_PI, "F4")   ; 式構文、連結
```

> FORM 構文の完全な説明は [FORM 構文](form-syntax.md) を参照してください。

## よくある落とし穴

| 落とし穴 | 誤った書き方 | 正しい書き方 | 原因 |
|----------|-------------|-------------|------|
| A-Z を変数名に使用 | `#DIM A` | `#DIM L_A` | A~Z はエンジン組み込みの汎用変数 |
| 文字列に引用符を付けない | `S '= hello` | `S '= "hello"` | 引用符なしは変数名として扱われる |
| 整数を文字列に代入 | `S = 42` | `S '= TOSTR(42)` | 型が一致しない |
| 浮動小数点数を整数に代入 | `X = 3.14` | `X = TOINT(3.14)` | 浮動小数点数を整数に代入すると 3 に切り捨てられる |
| 四捨五入を期待 | `TOINT(3.7)` で 4 を期待 | 手動実装：`TOINT(3.7 + 0.5)` | TOINT は切り捨てであり四捨五入ではない |
| 整数除算の意外 | `10 / 3` で 3.33 を期待 | `10 / 3.0` | 除算のオペランドがすべて整数の場合、整数除算となる |
| FORM 中での予期せぬ補間 | `S = 100%` | `S = 100\%` または `S '= "100%"` | `%` は FORM 構文で変数置換文字 |
| #DIM の位置が間違っている | `@F` → `PRINTL` → `#DIM` | `@F` → `#DIM` → `PRINTL` | #DIM は @ 行の後、実行ステートメントの前に必須 |
