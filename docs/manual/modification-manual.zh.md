### 理解基本文件结构  

era的基本文件结构如下  
- Emuera◯◯.exe  
- CSV文件夹  
- ERB文件夹  

CSV文件夹中放置了，  
角色状态、能力、特质、经验、道具等  
系统使用的数据，以CSV格式(以逗号分隔的文本)保存。  

ERB文件夹中放置了，记录动作的程序代码。  

基本上  
如果只想修改角色等数据，就修改CSV文件夹内容，  
如果想修改处理，就修改ERB文件夹内容。  

CSV只有固定文件名(`Chara○.csv`或`Talent.csv`等)才会被读取，所以创建`a.csv`等也没问题，  
**ERB会读取ERB文件夹内所有扩展名为.ERB的文件**  
如果在ERB文件夹内放置备份，要把扩展名改掉。

### 编辑角色  
打开CSV文件夹的`Chara○.csv`。应该能看到很多以`,`分隔的字符串。  
`Chara0.csv`在大多数变体中是主人公，`Chara1.csv`以后是调教对象的角色数据。  

角色数据按以下顺序，以逗号分隔写入。  

- 编号  
角色编号。在脚本中通过 `NO` 变量引用，即角色注册编号 (NO)。  
大多数情况下，这是`Chara○.csv`中`○`的相同数字。  

- 姓名  
- 称呼  
菜单显示如"○○调教中"等用姓名，调教中的口上等用称呼。  
所以，姓名填全名，称呼填昵称或缩短的叫法。  

- 基础  
大多数变体中`基础,0`是体力最大值，`基础,1`是气力最大值。  
主人公或男性角色才有，`基础,2`是射精计量。  
`基础,2`以后如果没有通常会用适当值初始化，所以不必特意给没有的角色添加。  

- 特质  
特质有无。`素質,○`表示"有○号特质"。  
编号与`Talent.csv`对应，所以查看`Talent.csv`后修改。  

- 能力  
初始能力。`能力,○,△`表示"○号能力有△级"。  
编号与`Abl.csv`对应，所以查看`Abl.csv`后修改。  

- 经验  
初始经验。`経験,○,△`表示"○号经验有△"。  
编号与`exp.csv`对应，所以查看`exp.csv`后修改。  

- 相性  
根据变体不同，但`相性,○,△`多表示"被角色注册编号 (NO) ○的角色**调教时的**效果为通常的△%"。  
注意是○号角色→此角色，而不是○号角色←此角色。  
未写的角色是100%，即±0。  

- 标志  
写入脚本引用的数据部分。  
根据变体完全不同意义，  
气力增加10倍，与你的相性最佳，  
添加`[处女]`，添加`[恋慕]`，删除`[快感的否定]`…随心所欲试试看。

### 增加持有资金  
在ERB中搜索`MONEY =`等，  

```  
MONEY = 10000  
```  

这样的描述，所以把数字改为想要的值  

大多数变体中`MONEY`存入当前持有资金值。像`MONEY`这样的值的容器叫做**变量**。  
`MONEY = 10000`不是" MONEY和10000相等"的意思，  
而是"向变量MONEY存入数值10000"的处理。  

另外，查找文件时，  

>@EVENTFIRST  

应该有这一行。像```@xxx```这样开始的脚本块叫做**函数**。  
`@EVENTFIRST`是选择[0]从头开始时调用的函数。  
大多数情况下，游戏初始化设置或游戏模式选择都在此函数中进行  

---  

### 不减少持有资金  
应用上述内容，即使多次购物也能保持持有资金不减少，持续为固定值。  
关键是向游戏中多次调用的函数中写入`MONEY = 10000`。  

这里说明移动到商店画面时保持持有资金为固定值的方法。  
`SHOP.ERB`(文件名根据变体)开头的`@EVENTSHOP`或`@SHOW_SHOP`是每次进入商店画面时调用的函数。  
在其中写入`MONEY = 10000`，每次进入商店画面时持有资金都会变为`10000`。  
"这样购物时没钱了怎么办"这种贪婪的人，可以写入下方的`@EVENTBUY`函数。（根据变体可能为其他函数）  
这是每次购买道具时调用的函数，所以在函数末尾设置持有资金，  
买什么都不会减少金钱。  

或者，也可以用以下方法。  
在ERB文件夹中，新建ERB文件(新建→文本文件→重命名扩展名即可)。  
扩展名为`.ERB`则名称可自由设置。  
然后在其中写入以下3行。  

>@EVENTBUY  
>#LATER  
>MONEY = 10000  

"`@EVENTBUY`在`SHOP.ERB`中已经有了。有2个相同函数没关系吗？"**没关系。**  
`@EVENTSHOP`或`@EVENTBUY`，之前的`@EVENTFIRST`等是称为**事件函数**的特殊函数，  
有相同名称的函数多个也能全部执行。  
所以，在某个时机(调教开始时、调教命令执行时、调教结束时等)想要  
执行数种事件时非常有用。最好的例子是**口上**。  

第2行的`#LATER`是只在事件函数中可用的**性质**设置行。  
`#LATER`的意思是"如果有多个`@EVENTBUY`，此`@EVENTBUY`最后执行"。  
还有最先执行的`#PRI`，不再执行其他相同事件函数的`#SINGLE`等性质。

### 将体力·气力减少减半  
`SOURCE.ERB`(文件名根据变体)的最后部分有以下部分。  

``` { #language-erb title="ERB" }  
;-------------------------------------------------  
;体力·气力减少  
;-------------------------------------------------  
BASE:0 -= LOSEBASE:0  
BASE:1 -= LOSEBASE:1  
;PRINT 体力-  
;PRINTV LOSEBASE:0  
;PRINT  气力-  
;PRINTVL LOSEBASE:1  
```  

`BASE:0`、`BASE:1`分别指体力、气力，  
`LOSEBASE:0`、`LOSEBASE:1`分别指体力减少、气力减少。  
所以试着添加以下2行。  

``` { #language-erb title="ERB" }  
;-------------------------------------------------  
;体力·气力减少  
;-------------------------------------------------  
LOSEBASE:0 /= 2 ;添加的部分  
LOSEBASE:1 /= 2 ;添加的部分  
BASE:0 -= LOSEBASE:0  
BASE:1 -= LOSEBASE:1  
;PRINT 体力-  
;PRINTV LOSEBASE:0  
;PRINT  气力-  
;PRINTVL LOSEBASE:1  
```  

`/= 2`是除以2的意思，也可以写成以下形式，但这样更简洁。  

> LOSEBASE:0 = LOSEBASE:0 / 2
